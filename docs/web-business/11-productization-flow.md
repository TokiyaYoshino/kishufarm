# 商品化のフロー — 事業の定義から、売れる商品まで

> 作成 2026年9月28日 / 対象読者: メンバー全員 / Artifact: なし（この Markdown が正）
> 前提: [10-positioning.md](10-positioning.md) の一文と、5段階の提案の型

10章で「誰の、どんな課題を、どう解決するか」は決まった。
この章は、それを**値札のついた商品**にして、最初の数件を売り、直すまでの手順を並べたもの。

## 全体像

```
STEP 0  仮説を実績で確かめる        9/28〜10/5    ─┐ GATE A: 既存2社で数字が動いたか
STEP 1  パッケージを組み直す        〜10/12       ─┤
STEP 2  価格を決める               〜10/12       ─┤ GATE B: 値札が1枚にまとまったか
STEP 3  提供の手順を標準化する      〜10/19       ─┤
STEP 4  売るための道具を作り直す    〜10/26       ─┤ GATE C: 商談に出せる状態か
STEP 5  テスト販売                 11月           ─┤ GATE D: 2〜3件の商談で何が起きたか
STEP 6  振り返って直す             12月           ─┘
STEP 7  契約・法務（並行）          3件目の受注前
```

期限の根拠は2つ。
- **補助金**: 持続化補助金 第20回は、12/4 までに商工会議所の書類、12/15 締切。補助金を使う顧客には**11月中に見積りを出す**必要がある → 商談道具は10月中に揃える
- **ANUHAIR 公開直後**: 実働時間の実測と、紹介依頼の両方の最大タイミング

各STEPの終わりに**GATE（進んでよいかの判断）**を置く。GATEを通らなければ、前のSTEPに戻る。

## STEP 0. 仮説を実績で確かめる（9/28〜10/5）

10章の一文は、まだ仮説。既存2社で確かめる。

| やること | 担当 | 成果物 |
|---------|------|--------|
| ANUHAIR・がめ吉珈琲の店主に聞く（10章 06 のチェックリスト） | 代表 | ヒアリングメモ |
| 公開前後の「予約経路の内訳」と「ポータルへの支払い」を並べる | 代表 | 1枚の比較表 |
| ANUHAIR の実働時間を集計する（コミット履歴・作業記録から） | 代表 | 1件あたりの実働時間（92h/件の仮定を置き換える） |
| 同じ場で**紹介を依頼する**（紹介者に渡す1枚を持参） | 代表 | 紹介先の候補リスト |

### GATE A — 数字は動いたか

| 結果 | 次の行動 |
|------|---------|
| 自前経由の予約が増えた / ポータル支払いが減った | そのまま STEP 1 へ。**この数字が商談資料の実績になる** |
| 変化はないが、原因の段階が特定できた（例: LINE登録の導線がない） | その段階を商品の必須項目にして STEP 1 へ |
| 何も分からない（数字が取れない） | 数字を取る仕組み（予約経路の記録）を2社に入れ、STEP 1 は並行で進める。実績欄は「導入事例」に留める |

### STEP 0 の結果（9/28 代表への聞き取り）

| | ANUHAIR（美容室） | がめ吉珈琲（カフェ） |
|---|---|---|
| ポータル | 使っていない | 無料掲載のみ |
| ポータルへの支払い | 0円 | 0円 |
| 予約 | LINE予約は未導入。**店主は欲しがっている** | 予約を取らない店 |
| サイト | **未公開**（目標7月末から約2ヶ月遅れ。デザイン・素材待ち） | 公開済み |
| 新規客の入口 | 紹介・コミュニティ | 紹介・コミュニティ |

**判定: GATE A は「数字が取れない」ケース。** そもそも既存2社は10章で想定した「ポータル依存の店」ではなかった。

**分かったこと — 顧客は2種類いる**

| | A. ポータル依存の店 | B. ポータルを使っていない店（既存2社） |
|---|---|---|
| 困っていること | 毎月の固定費と手数料が重い | 紹介・コミュニティ以外の新規の入口がない |
| 当社の提案 | 段階的に自前の集客へ置き換え、支払いを減らす（10章） | ポータルに払う前に、無料の入口（Google・AI検索）とLINEを整える |
| 予算 | 集客に年40〜100万円使っている → 価格の説明がしやすい | 集客にお金を使う習慣がない → 価格の説明が難しい |

- 商品の中身（①入口 ②つながる ③月額）は A・B 共通。変わるのは商談の最初の話し方だけ
- B は紹介で客が来ている。**紹介された人も来店前に店名を検索する**ので、GBP・サイトは紹介の取りこぼしを防ぐ受け皿にもなる
- B の店は予約台帳を使っていないので、**自作のLINE予約でも二重予約の問題が起きない**（A の飲食店とは扱いが違う）

**決定: 実績は B（既存2社）で作り、営業は A から始める。**
A はすでに集客にお金を使っているので「その1年分以下で」と価格を説明できる。

**ANUHAIR が未公開なのは好都合。** 公開前の数字を今のうちに記録しておけば、きれいに前後比較ができる。
- [ ] GBPの表示回数・電話・経路検索（GBPの管理画面、公開前の3ヶ月分）
- [ ] 月の新規客数と、その入口（店主の感覚でよい）
- [ ] 半年後に「ポータルに1円も払わずに、新規がこれだけ増えた」と言える形にする

**STEP 3 への宿題 — 素材待ちで2ヶ月止まった。** 受注件数が増えると、これが一番の詰まりになる。
素材の締切と、素材が揃わないときの進め方（仮素材で公開して後から差し替える、等）を提供フローと契約に入れる。

## STEP 1. パッケージを組み直す（〜10/12）

いまの PLAN01/02/03 は**機能の多さで段になっている**。10章の5段階に合わせて**課題で段を切り直す**。

### 組み直し案

| 新しい構成 | 解決する課題 | 中身 | 旧プランとの対応 |
|-----------|------------|------|----------------|
| **① 入口をつくる** | ポータル以外から見つけてもらえない | サイト、GBPの整備、構造化データ（AEO）、口コミ依頼の導線 | PLAN01＋PLAN03の一部 |
| **② お客さんとつながる** | 来た客が1回で終わる、常連にも手数料を払っている | LINE登録の導線（店頭QR・POP込み）、来店後のお礼と口コミ依頼、再来の案内。**業種別の中身は下** | PLAN02・03の一部 |
| **③ 育てる（月額）** | 効果が見えない、ポータルをいつ減らせるか分からない | 月次レポート（10章の5指標）、GBP更新、AEO引用チェック、軽微な更新、**ポータル見直しの提案** | PLAN03の月額保守 |
| オプション: EC | 自分でコントロールできる売上がない | 自社EC。LINE友だちへの告知とセット | PLAN02のEC |
| オプション: 業務自動化 | 手作業が多い | gas-ops | 既存 |

**業種別の②の中身**

| | 飲食店（カフェ） | 美容室 |
|---|---|---|
| 予約 | **予約システムは作らない**。店が使っている台帳のLINE連携・Googleで予約を設定 | SALON BOARD と空き枠が二重にならない形にする（STEP 0 の ANUHAIR の答え次第） |
| 再来の仕掛け | 来店後のLINE、季節メニューの告知 | カット周期に合わせた「そろそろ」の案内、次回予約 |
| 追う数字 | 自前経由の予約の割合 | 新規の再来率 |

### 決めること

| # | 論点 | 推奨 |
|---|------|------|
| 1 | ①だけの販売を認めるか | **①単体は売らない**。②がないと10章の課題を解決せず、効果が出ないまま「作って終わり」になる。予算が合わない場合は ①＋③（月額）で入り、②を後から足す |
| 2 | ③（月額）を必須にするか | **必須にする**。段階4（ポータル見直し）まで伴走しないと、店主が得るはずの「固定費が減る」が実現しない |
| 3 | 何を「作らない」と決めるか | 予約システムの自作（飲食）、広告運用、コンテンツ制作・外部での言及獲得（月額に含めない） |

### 決定事項（9/28）

- **デザインは当社（代表）が作る**のを標準とする。ANUHAIR は例外（店主側で事前にデザインを用意していた）
- **①単体は売らない。** 予算が合わない場合は ①＋③ で入り、②を後から足す
- **③（月額）は必須**

### LINE予約（検討中・9/28）

**需要**: 美容室を予約する女性のうち、LINEで予約するのは全体の約4%（ネット予約56.0% × そのうちLINE 7.4%、美容センサス2025年上期。二次情報経由で原典未確認）。
2022年の5.9%から増えているが、主に常連の予約手段。新規の入口はポータルが圧倒的。
店主が欲しがる理由は客の便利さより**自分の手間**（施術中に電話に出られない、リマインドで無断キャンセルを減らす）。

**ANUHAIR のLINE予約は未実装。** 店主は欲しがっている。

**費用の比較**（店の月額負担）

| | 自作（LIFF） | 既製品の無料プラン | 既製品の有料プラン |
|---|---|---|---|
| ツール代 | 0円（DB等は無料枠内） | 0円 | 月5,500円前後〜 |
| 制限 | なし | STORES予約は月50件まで等。サービスごとに違う（要確認） | ほぼなし |
| 当社の工数 | 数十時間＋保守 | 数時間（選定と設定） | 数時間 |
| LINEの配信料 | **どちらでも同じようにかかる**（下記） | | |

**本当のランニングコストはLINE公式アカウントの配信料。**
コミュニケーションプラン0円は月200通まで、ライトプラン月5,000円で5,000通（2026年10月に追加料金の体系が改定予定）。
月150件の予約に確認とリマインドを送ると300通になり、無料枠を超える。自作でも既製品でも同じ。
→ 配信の設計（何を、誰に、月何通）で、店の月額が0円か5,000円かが決まる。これは当社が設計する部分。

**推奨**: 自作しない。既製品の無料プランを、LINEのリッチメニューからリンクする形（誘導型）で設定する。
無料枠を超えたら有料プランに上げる。自作するのは、同じ仕組みを3店以上で使い回せると分かってから。

### 決定: 予約は Google 連携の既製品で受ける（9/28）

**要件**（代表）
- GBPを使う前提なので、**Googleと連携できること**
- **メニューごとの所要時間**で空き枠が変わること

**比較**

| | Googleカレンダー 予約スケジュール | STORES予約 | **Square予約** |
|---|---|---|---|
| 無料で使えるか | 使える | 使える（月50件・2ページまで） | 使える |
| Googleマップから直接予約（Googleで予約） | できない（リンクで移動） | 対応 | **対応** |
| メニューごとの所要時間 | **無料では不可**（予約ページ1つのみ） | 可 | **可** |
| 自動リマインド | 無料では不可 | 可 | **メール・SMSで可** |
| 無料の制限 | 予約ページ1つ | 月50件。Googleカレンダー連携は有料のみ | **実質スタッフ1名**（複数スタッフ管理は有料） |
| 有料プラン | Workspace / Google One（料金未確認） | 月12,980円〜（高い） | 未確認 |

**決定: 標準は Square予約（無料プラン）。**
- 所要時間・Googleで予約・リマインドが無料で揃う。件数の上限の記載はない（要確認）
- スタッフが2名以上の店は、有料プランの料金を確認してから見積りに入れる
- Squareは決済（約2.5%）も同じ会社なので、事前決済を入れる場合もまとめられる
- Googleカレンダーの予約スケジュールは、所要時間の要件を満たさないため標準にしない

**スタッフ2名以上の店**: Square予約 プラスプラン **月3,000円**（複数スタッフ、Googleカレンダー同期、無断キャンセル対策、メール・SMSの予約確認）。
店の負担として見積りに明記する。年3.6万円で、HPBの年額（約50万円〜）の1割以下。
※ 自動リマインド・確認通知が無料プランに含まれるかは、記事によって記載が違う。設定時に確認する。

**既存2社への適用**

| | 予約 | 備考 |
|---|---|---|
| ANUHAIR（スタッフ2名） | Square予約 プラスプラン（月3,000円） | 店主が欲しがっていた。LINE予約は自作しない |
| がめ吉珈琲 | **なし** | 予約を取らない店。②は予約以外（LINE登録・お知らせ）で組む |

**LINEの役割**: 予約を受ける場所ではなく、**予約ページへの入口（リッチメニュー）と、来店後のつながり**。

**流れ**: Googleで見つける（GBP・AEO）→ Googleで予約（Square予約）→ 来店後にLINEでつながる

※ 各サービスの機能・制限は検索結果の要約に基づく。設定前に各サービスの画面で確認すること。

**成果物**: パッケージ定義書（各構成に「含むもの／含まないもの／納品物／店主にやってもらうこと」）

## STEP 2. 価格を決める（〜10/12）

9月中の期限だった価格の方針（TODO B1）は、ここで決める。10章の考え方で**価格の比べる相手が変わる**。

- これまで: 他の制作会社の相場と比べていた（平均発注額67.7万円）
- これから: **店がポータルに払っている年額**と比べる（飲食 年40〜180万円、美容 年50〜320万円）

### 価格の組み立て方

| 構成 | 価格の考え方 | 仮の価格帯 |
|------|------------|-----------|
| ①＋② 初期 | ポータル支払いの**1年分以下**で、店に資産が残る | 45〜70万円（値上げ案の PLAN02〜03 相当） |
| ③ 月額 | 保守料の相場（月0.5〜3万円）の中。ポータルの月額より十分に安い | 月1.5〜2万円 |
| 補助金を使う場合 | ウェブ関連費の上限30万円（補助額最大20万円）を前提に、①＋②の見積りを組む | — |

## STEP 3. 提供の手順を標準化する（〜10/19）

売れた後に毎回ゼロから考えないよう、受注から月額までの流れを固定する。**ここが決まると実働時間が読めるようになる**。

### 提供フロー（受注後）

| # | 工程 | 期間の目安 | 店主にやってもらうこと | 当社の成果物 |
|---|------|----------|---------------------|------------|
| 1 | **現状診断** | 初回商談 | ポータルの請求書と、予約経路の感覚値を見せてもらう | 集客コスト診断シート（年額、常連に払っている額） |
| 2 | 設計 | 1週間 | ページに載せる情報、写真 | 構成案、LINEの配信シナリオ案 |
| 3 | 制作（①） | 2〜4週間 | 確認・修正依頼 | サイト、GBP、構造化データ |
| 4 | つながる仕組み（②） | 1〜2週間 | LINE公式アカウントの開設（当社が同席） | LINE導線、店頭QR・POP、配信シナリオ、台帳の連携設定 |
| 5 | 公開・引き渡し | 1日 | スタッフへの周知（「LINE登録をお願いする」の一言） | 使い方の説明、**公開時点の数字の記録（基準値）** |
| 6 | 月額（③） | 毎月 | — | 月次レポート（5指標）、GBP更新、引用チェック |
| 7 | **ポータル見直しの提案** | 6ヶ月目 | プランを下げるかの判断 | 自前経由の推移と、下げた場合の試算 |

### 標準化するもの

| もの | 目的 |
|------|------|
| ヒアリングシート | 工程1で必ず聞く項目を固定（ポータルの支払い、予約経路、客単価、来店数、新規数） |
| 業種別のサイトのひな形（飲食・美容） | 工程3の工数を減らす。**著作権を当社に留保する条項が前提**（STEP 7） |
| LINE配信シナリオのひな形（業種別） | 工程4を毎回考えない |
| 月次レポートのひな形 | 工程6を1時間以内に収める |
| 作業時間の記録 | 工程ごとの実働時間を毎回記録し、価格の根拠にする |

## STEP 5. テスト販売（11月）

- **チャネル**: 紹介（STEP 0 で得た候補）と商工会議所（柏・横浜）。コールドは使わない（09章）
- **目標**: 商談2〜3件、成約1〜2件。件数より**記録**が目的
- **補助金案件**: 11月中に見積りを出す。着手は交付決定後（年明け）

商談ごとに記録すること

| 項目 | なぜ |
|------|-----|
| 診断シートで出た年額 | 価格が「ポータル1年分以下」に収まっているかの検証 |
| 一文への反応（刺さった言葉、刺さらなかった言葉） | 営業トークの修正 |
| 成約価格と値引きの有無 | 価格の検証（TODO C3） |
| 断られた理由 | 価格か、中身か、タイミングか |

**GATE D — 何が起きたか**
- 「価格」で断られた → STEP 2 に戻る
- 「効果が分からない」で断られた → STEP 0 の実績の見せ方、診断シートを直す
